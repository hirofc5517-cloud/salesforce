# レポート・ダッシュボード 標準リファレンス

データの集計・可視化はまず標準のレポート・ダッシュボード機能で実現できないかを検討します。
（LWCで独自グラフを作る前に、必ずここを確認すること）

## 1. 標準レポートタイプ

- Salesforceはオブジェクト間の関係に基づき**標準レポートタイプ**を自動生成する。
  カスタムオブジェクト同士の関連も「カスタムレポートタイプ」を作成することで、コード不要で
  複雑な集計・絞り込みが可能。
- レポート形式: 表形式（Tabular）／サマリー（Summary、グルーピング集計）／
  マトリクス（Matrix、縦横グルーピング）の3種類を要件に応じて使い分ける。

## 2. ダッシュボード

- ダッシュボードコンポーネント（棒グラフ、チャート、メーター、指標、テーブル等）でレポートを可視化。
- 動的ダッシュボード（実行ユーザーの権限で表示）を使うことで、ユーザーごとに見える範囲を
  自動的に絞り込める（Apex/LWCでの独自権限フィルタ実装が不要になる）。
- レポートのグラフをLightningページやLWCに埋め込むことで、多くの「独自グラフ作成」要件は
  標準コンポーネントで代替可能。

## 3. 標準機能の制限（要件がこれを超える場合のみコード検討）

| 項目 | 制限の目安 |
|---|---|
| レポートの表示行数（実行時） | 2,000行（表示上限。集計値自体は全件対象） |
| レポート内の項目数 | 上限あり（多すぎる場合は複数レポートに分割） |
| ダッシュボードの自動更新頻度 | 最短1時間ごと（それ以上の頻度が必要ならリアルタイム表示コンポーネントを検討） |

## 4. 実装前チェックリスト

- [ ] 標準レポートタイプ／カスタムレポートタイプで集計要件を満たせないか確認したか
- [ ] ダッシュボードコンポーネントで可視化要件を満たせないか確認したか
- [ ] 動的ダッシュボードでユーザーごとの表示制御ができないか確認したか
- [ ] それでも不足する場合のみ、LWC + Apex(集計ロジック)を検討したか
