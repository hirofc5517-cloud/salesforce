# 自動化・実装手段の選定ガイド

Salesforceで「何かを自動化・実装したい」となった際、どの機能を使うべきかを判断するための基準です。
**上から順に検討し、要件を満たせる最も宣言的（設定ベース）な機能を採用**してください。

## 判断フローチャート

```
要件がある
  │
  ├─ UIの表示/入力制御だけで済むか？
  │    → はい: ページレイアウト / Dynamic Forms / 項目の必須設定 / 制御項目・依存項目 で対応
  │
  ├─ 「この値は不正」という入力チェックか？
  │    → はい: 入力規則（Validation Rule） で対応
  │
  ├─ 既存項目からの単純な計算・参照表示か？
  │    → はい: 数式項目（Formula Field） で対応
  │
  ├─ 子レコードの合計/最大/最小/件数を親に集計したいか？（マスタ商細関係のみ）
  │    → はい: ロールアップ集計項目（Roll-Up Summary） で対応
  │
  ├─ レコード保存を契機にした自動処理（項目更新・関連レコード作成・通知・承認開始等）か？
  │    → はい: Flow（レコードトリガーフロー） で対応
  │         - 同一レコードの項目更新のみ、保存前(before-save)で完結 → Fast Field Update可
  │         - 関連レコード作成・外部コールアウト等が必要 → after-save
  │
  ├─ 画面を介したユーザー操作の誘導（ウィザード的入力）か？
  │    → はい: Flow（画面フロー） で対応
  │
  ├─ 時間主導のバッチ的処理（毎日/毎週の一括更新等）か？
  │    → はい: Flow（スケジュールフロー） または 軽量なら Scheduled Flow、
  │            大量データ・複雑な条件分岐を伴うなら Apex Batch/Scheduled Apex
  │
  └─ 上記すべてで実現不可能、または以下に該当するか？
       - 複雑な分岐・ループを伴うアルゴリズム
       - 大量データに対する高度なSOQL最適化やトランザクション制御
       - 複雑な外部システム連携（再試行制御、独自の例外処理等）
       - 高い再利用性が必要なドメインロジック（複数のFlow/画面/バッチから呼びたい）
       - Flowでは表現困難な複雑な条件式・数値計算
       → Apex（トリガー / Invocable Apex / バッチ / キューアブル） で対応
          ※ 可能な限り「Flowから呼び出すInvocable Apexメソッド」として部品化し、
             Flow側で条件分岐やUI制御を担う「ハイブリッド構成」を優先検討する。
```

## 早見表

| やりたいこと | 標準機能 | Apexが必要になるケース |
|---|---|---|
| 項目の必須/読み取り専用切り替え | 入力規則・制御/依存項目・Dynamic Forms | 条件が非常に複雑で数式で表現不能な場合のみ |
| 保存時の項目自動計算 | 数式項目 / Flow(before-save) | 外部データ参照や複雑な反復計算が必要な場合 |
| 承認プロセス | 承認プロセス（Approval Process） | 動的な承認者決定ロジックが複雑な場合（Apexで承認者解決） |
| メール送信 | メールアラート（Workflow由来）/ Flowのメール送信要素 | 添付ファイル動的生成・複雑なテンプレート合成 |
| レコード共有 | 共有ルール・手動共有・Apex共有(Apex Managed Sharing)は最終手段 | 動的かつ複雑な共有条件のみ |
| 重複防止 | 重複ルール・一致ルール（標準機能） | 高度なファジーマッチングロジック |
| データ一括処理 | Flow(スケジュール) / データローダー | 大量件数・複雑分岐・再実行制御が要る場合はBatch Apex |
| 外部システム連携 | Named Credential + External Services + Flow | 複雑なリトライ・非同期コールバック処理 |
| UI独自表示 | 標準ページ/コンポーネント/Dynamic Forms | 標準コンポーネントで表現不可能なUXのみ LWC |

## 非推奨・使用禁止の機能

以下は新規実装では使用しないこと（Salesforce社の非推奨方針）。

- **Workflow Rule（ワークフロールール）**: 新規作成不可（2022年10月より新規組織で新規作成停止）。既存はFlowへ移行。
- **Process Builder**: 2023年以降新規組織では作成不可。Salesforceは既存資産もFlowへの移行を推奨。
- 上記に該当する既存の自動化を見つけた場合は、機能追加ではなく **Flowへの移行** を提案すること。
