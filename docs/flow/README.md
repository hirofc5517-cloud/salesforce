# Flow 標準リファレンス

Flowは現在Salesforceが推奨する**唯一の宣言的自動化基盤**です（Workflow Rule / Process Builderの後継）。
Apexを検討する前に、必ずFlowで実現可能かを確認してください。

## 1. Flowの種類と用途

| 種類 | トリガー契機 | 主な用途 |
|---|---|---|
| **画面フロー (Screen Flow)** | ユーザーのボタン/タブ操作、LWC埋め込み | ウィザード型のデータ入力・案内 |
| **レコードトリガーフロー (Record-Triggered Flow)** | レコードの作成/更新/削除 | 項目自動更新、関連レコード作成、通知 |
| **スケジュールトリガーフロー (Scheduled Flow)** | 指定日時・定期実行 | 一括更新、リマインド処理 |
| **プラットフォームイベントトリガーフロー** | Platform Eventの受信 | イベント駆動の疎結合連携 |
| **自動起動フロー (Autolaunched Flow)** | Apex/他Flow/API等から呼び出し | 再利用可能なサブフロー部品 |

## 2. レコードトリガーフロー：before-save vs after-save

- **before-save（保存前）**: 同一レコードの項目更新のみ可能。**追加DMLが発生しないため高速**
  （"Fast Field Update"）。関連レコード作成やメール送信は不可。**最優先で検討する**。
- **after-save（保存後）**: 関連レコードの作成/更新、メール送信、外部コールアウト（要非同期）などが可能。
  ただし追加のDMLが発生し、トリガー的な処理コストがかかる。

**選定ルール**: 「このレコード自身の項目を更新するだけ」なら必ずbefore-saveを使う。

## 3. エントリ条件・実行順序

- エントリ条件（entry condition）は「更新の場合のみ、かつ条件を満たしたレコードのみ」まで絞り込み、
  不要な起動を避ける（性能・保守性のため）。
- 同一オブジェクトに複数のレコードトリガーフローを乱立させない。**設定 → プロセスの自動化 → フロー**
  で「トリガーの順序（Order）」を明示的に管理する。
- Apexトリガーと混在させる場合は実行順序（Before Flow → Before Apex Trigger → System Validation
  → After Apex Trigger → After Flow → Assignment Rules → Auto-Response Rules → Workflow Rules →
  Processes/Flows → Escalation Rules...）を理解した上で設計する。

## 4. エラーハンドリング

- 外部コールアウトやDML操作を伴う要素には必ず**フォルトパス（Fault Path）**を接続する。
- フォルトパスなしで例外が発生すると、ユーザーには不親切なデフォルトエラー画面が表示される。
  カスタム通知・エラーログ記録（カスタムオブジェクトへの記録等）を検討する。
- `Get Records` 等でレコードが0件の場合の分岐（decision要素）を必ず用意する（null参照エラー防止）。

## 5. 再帰・パフォーマンス規約

- レコードトリガーフロー内で同一オブジェクトを更新する場合、**無限再帰**に注意する
  （before-saveの自己項目更新は再帰トリガーにならないが、after-saveでの自己更新DMLは再帰を招くため
  極力before-saveで完結させる）。
- ループ内で `Get Records` / DML要素を実行しない。ループ前に一括取得し、コレクション変数に格納してから
  ループで処理し、**ループ外で一括更新（Update Records要素、コレクション単位）**する
  （Apexのバルク化原則と同じ考え方）。
- サブフロー呼び出しの多用はデバッグ性を下げるため、明確に再利用性がある場合のみ分割する。

## 6. Flowの主な制限値

| 項目 | 制限値 |
|---|---|
| レコードトリガーフロー：1トランザクションあたりの要素実行 | 2,000 |
| SOQL発行 | Apexと共通のガバナ制限内（100回） |
| ループの最大反復（実質） | ガバナ制限（CPU時間等）に準拠 |
| フローの相互呼び出し深さ | 上限あり（過度なネストは避ける） |

具体的な数値はSalesforceのリリースにより変動するため、実装前に最新のガバナ制限を
Salesforce公式ドキュメント（Flowの制限）で確認すること。

## 7. Flowを書く前のセルフチェックリスト

- [ ] before-saveで完結できないか（同一レコードの項目更新のみか）を確認したか
- [ ] エントリ条件で不要な起動を絞り込んだか
- [ ] DML/コールアウトを伴う要素にフォルトパスを接続したか
- [ ] ループ内でGet Records/DML要素を呼んでいないか
- [ ] 同一オブジェクトの既存自動化（他のFlow/Apexトリガー）と競合・重複しないか確認したか
- [ ] Process Builder/Workflow Ruleを新規作成していないか（禁止）
